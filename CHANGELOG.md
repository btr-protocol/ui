## 0.12.3
- Connect modal, Recent rows: the row is one surface. The remove button no longer sits in a separate cell with its own background: it is a 44 px box overlaying the row's inline end (`.row-x` / `.row-x-btn`, logical properties, RTL safe), so the hover, keyboard-highlighted and focus background and the accent border cover the whole row width. `CloseButton`'s `onClick` now receives the click event.
- Remove button reveal, hover-capable pointers: hidden at rest, no space and no clicks (a click where it would be lands on the row), so the "Detected" tag has the same right edge in Recent and Installed rows. On row hover or keyboard focus inside it fades in, the tag slides 32 px inline-start (padding transition, none under `prefers-reduced-motion`), and it takes clicks once the slide has run (180 ms), so a quick click aimed at the tag still hits the row. Tab reaches it at any time (name "Remove <wallet> from recent wallets"). While the button has keyboard focus (`:focus-visible` inside, via `:has`; a mouse click leaves nothing stuck) the row shows the hover surface.
- Remove button on touch (`hover: none`): always shown at full opacity. Every row of Recent, Installed and Other (`.wallet-rows`) reserves the same 44 px trailing gutter, so tags, remove buttons and the external-link icons share one trailing edge.
- While a connection is pending every row is disabled and so is the remove button (hidden, no clicks), so the wallet being connected cannot be dropped from the gutter. `CloseButton` takes `disabled`.
- Keyboard reveal does not depend on `:has()`: keyboard focus on the remove button shows it and arms it instantly (no 180 ms delay) through its own `:focus-visible` rule; `:has` only adds the row surface and the tag slide, so without `:has` the focused button overlaps the tag (fallback). With `prefers-reduced-motion` the button is armed the moment it is shown (the 180 ms arming delay applies to full motion only).
- Removing a recent keeps keyboard focus in the list: the next row's remove button, else the previous one, else the search box (else the first Installed row).
- `WalletGlyph`: an image mark (bundled raster or announced EIP-6963 icon) sits on a fixed light neutral tile, `--wallet-tile-bg` / `--wallet-tile-fg` (tokens.css, same value in dark and light), so a transparent icon no longer shows the page surface as a dark hole next to the brand tiles. The generic wallet glyph was drawn under every image and showed through its transparent areas; it now shows only until an image has loaded, on the dark `bg-bg-3` tile as before, which is also what a failed load ends on. The generic-glyph tile and `bare` marks (WalletConnect tile) are unchanged.
- `WalletGlyph` fix: the effect that restarts the degradation order ran on mount, after paint, and reset an error that had already fired (a broken `data:` URI fails before the effect) back to stage 0, leaving the dead image on the tile and the glyph under it. It now runs only when the wallet id or announced icon changes.
- Test: `test/wallet-rows.browser.test.tsx` (Chromium; `KIT_ROOT=<other checkout>` runs it against another tree), fixture `test/fixtures/wallet-page.tsx`.

## 0.12.2
- SIZE CHANGE (touch): on `pointer: coarse` every tab in a strip (group and attached; xs, sm and md) is at least `--ctl-m` (44 px) tall and wide. An xs tab was 32 px tall there, so an xs TAB STRIP is now 46 px (44 plus the group's two 1 px borders, the same as sm and md) while a plain xs `ButtonGroup` stays 34 px. Why they differ: a standalone button keeps its 44 px hit area through its `::after`; a tab inside the scroller cannot (the scroller clips the pseudo, and inside a strip it is zeroed because it overflowed the scroller by 1 px), so the tab's own box carries the floor. The 0.12.0 "pixel-identical to a button group" statement holds for sm and md on touch and for every size on fine pointers; the one exception is xs on a coarse pointer. On a phone, `xs` now means type size and padding only. Desktop is unchanged (xs strip 26 px).
- Widths on touch (re-measured at 390 px): a 1-character tab ("$") goes from 22.7 to 44 px, so `$ | APR` at xs goes from 66.4 to 90.0 px in total; the 4-option range strip (`1D 1W 1M 1Y`, sm) goes from 176.5 to 180.5 px in total, its short tabs to 44 px each. Strips that scroll keep their widths; their height changes with the rest.
- CONSUMER ACTION: check xs tabs next to xs Buttons or Inputs on phones (they are now 46 px against 34 px), rows with a fixed height under 46 px, and short `equal` strips (each tab is now at least 44 px wide).
- Hover no longer reads as selected: an unselected tab in a group presentation filled `bg-primary` on hover, the selected fill. It now takes `--bg-3` and `--fg-0`, as attached tabs did, and both only where hover exists (`hover: hover`), so an attached tab no longer keeps a hover tint after a tap. A selected tab keeps its look. A disabled tab does not change on hover (its idle fill is pinned, group and attached).
- False start-edge fade: the centring step no longer runs, and `data-l` / `data-r` are not set, when a strip lacks 2 px or less of its content (a shrink-wrapped group whose container is 1 to 2 px short, which centring scrolled by 1 to 2 px and dimmed the first tab). Real overflow is unchanged.
- RTL: `data-l` / `data-r` are the start / end edges (scrollLeft is negative in RTL) and the fade mask mirrors with `:dir(rtl)`.
